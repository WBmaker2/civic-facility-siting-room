# Elementary Web App Simulation Decision

작성일: 2026-08-31
대상: `도시 기능 입지 심의실`

## 결정

결정 장부: `not-needed`

새 Canvas/WebGL/게임 엔진 또는 시간 기반 시뮬레이션은 추가하지 않습니다. 현재 앱의 핵심 학습 목표는 실제 도시를 재현하는 물리 시뮬레이션이 아니라, 고정된 가상 격자와 도로 그래프에서 후보를 바꾼 뒤 평균·최대·도달 불가·위험·비용을 비교하고 주민 관점의 근거를 설명하는 것입니다.

## 근거

| 루브릭 질문 | 현재 앱 증거 | 판단 |
|---|---|---|
| 조작 전 예측 | 우선 기준 카드와 후보지 비용·위험·도로 설명 | 이미 한 변수(후보지)를 바꾸기 전 예상할 자료가 있음 |
| 조작 → 관찰 | `analyzePlacement`가 결정적으로 결과표를 만들고 평균·최대 카드를 제공 | 목표 루프가 충족됨 |
| 설명 → 재시도 | A안 저장 → 후보 수정 → B안 저장 → 변화 목록과 의견서 문장 프롬프트 | reset 대신 제안 비교 자체가 학습상 핵심 |
| 시간·pause·step | 시간에 따라 변하는 상태가 없고 각 계산은 즉시 완료 | pause/step은 적용 대상이 아니므로 N/A |
| 키보드·터치 대안 | 네이티브 입력, 지도 grid의 화살표·Enter/Space, 표 보기 | 별도 캔버스 조작이 필요하지 않음 |
| reduced motion | `gi-pulse` 정적 외곽선, `FacilityRange` 정지 표시 | 모션 없이 표·수치·설명으로 학습 가능 |
| 모델 한계 | 실제 도시·실제 측정값·응급 성능이 아니라는 `MODEL_LIMIT_NOTICE` | 실제 예측·안전 보장으로 과장하지 않음 |

## 관찰한 학습 루프

```text
자료층 두 개 켜기
  → 후보지 하나 선택
  → 영향 계산
  → 평균·가장 긴 이동 카드 확인
  → 불편한 구역 선택
  → A안 저장
  → 다른 후보지로 재계산
  → B안 저장
  → 변화와 절충을 문장으로 설명
```

이 루프에서 필요한 개선은 시뮬레이션 엔진이 아니라 정상 중간 상태 안내(EDU-UX-001), 완료 판정 문구(EDU-UX-002), 모바일 dialog 레이아웃(EDU-UX-003)입니다.

## 이미지·시각자료 결정

결정: `no-image-needed`

현재 `public/`·`src/assets/`에 핵심 이미지가 없고, 지도와 표는 후보 좌표·도로 연결·사람 토큰·위험 표지를 세어야 하므로 DOM 텍스트/무늬가 사실의 원본입니다. 장식 이미지를 추가하면 실제 도시 사진·지도처럼 오해할 위험이 있고, 핵심 수치·정답·접근성 정보를 대체할 수 없습니다. 따라서 imagegen을 호출하거나 이미지 자산을 만들지 않습니다.

## 범위 밖 역할

`game-studio` 시뮬레이션 전문 역할과 `build-web-data-visualization` 역할은 새 캔버스·시간 기반 차트가 필요하지 않아 호출하지 않았습니다. 표·DOM·결정적 엔진 검증으로 충분하며, 이 판단은 시뮬레이션 부재를 실패로 간주하지 않는 교육용 인터랙티브 정책과 일치합니다.
